# 0.1.0 Follow-up Plan

This plan records release-hardening work that is intentionally deferred. It is not part of the current changelog entry because these improvements are not yet implemented.

## Goals

Make repository mutations update the branch-history and canvas state immediately, and make branch synchronization data complete and reliable across refreshes.

## Work Items

### 1. Refresh cached history after Git mutations

- Update `execute_git_checkout`, `git_fetch_operation`, `git_pull_operation`, and `git_push_operation` in `src-tauri/src/git.rs` to complete the existing full repository refresh path before returning success.
- Reuse the refresh coordination in `src-tauri/src/manager.rs` and `src-tauri/src/refresh.rs` rather than relying on filesystem watcher timing.
- Preserve the current Git error behavior and ensure a failed refresh is surfaced instead of reporting a misleading successful operation.
- Verify that repository detail history, dashboard branch state, and canvas cards all reflect the mutation immediately.

### 2. Populate branch synchronization counts

- During branch reconciliation, calculate ahead and behind counts for local branches with upstreams using `git2`.
- Persist those values with `is_head` and the latest commit metadata in `cached_git_branches`.
- Define and test the behavior for branches without an upstream, missing upstream references, and repositories with no local branches.
- Confirm that dashboard and canvas sync indicators use the refreshed values for every branch, not only the checked-out branch.

### 3. Add regression coverage

- Add frontend coverage for repository-detail fetch, pull, and push actions followed by history refresh.
- Add dashboard coverage for checkout followed by updated current-head state.
- Add Rust coverage for branch ahead/behind calculation and cache persistence.
- Add canvas-store or `BranchMap` coverage for hydration after Git state changes, including persisted nodes, edges, viewport, and branch topology.
- Prefer existing Vitest and Rust test helpers; do not add end-to-end infrastructure unless the existing test boundaries cannot verify the contracts.

### 4. Validate and document the follow-up

- Run `npm test` and `npm run build` from the repository root.
- Run `cargo check` from `src-tauri`; use it as the required Rust validation if the known Windows Rust test-binary launcher issue prevents focused Rust tests from running.
- Run a Tauri desktop smoke test covering checkout, fetch/pull/push where available, branch history, and canvas persistence.
- Regenerate affected architecture, IPC, state, component, test, or database documentation if implementation changes make those generated artifacts stale.

## Scope Boundary

This follow-up does not include merge, rebase, cherry-pick, stash, worktree, branch rename/delete, or advanced conflict-resolution workflows. Those should be planned separately if they become release requirements.
